# US-00.15  AI connection check (Claude from the first build)

```text
ID and title:       US-00.15  AI connection check (Claude from the first build)
Epic / goal:        E-00 / G-01   (ai-docs/epics/E-00.md, ai-docs/goals/G-01.md)
Requirements:       D-11 (todo.md); FR-AI-05, FR-AI-06, FR-AI-07 (test call, reject with reason, memory only); ADR-032 (Claude only), ADR-033 (session-only key); E-ADR of the AI layer (engine-architecture.md 4, Spring AI ChatClient)
As a:               a developer (and later the client in the demo)
I want:             to enter my own Anthropic key on the skeleton page, send one test call to Claude through the backend and see the answer or the reason of the rejection
So that:            the AI path (browser → API → Spring AI → Claude) works from the first build and every developer can try it with their own key
Domain:             infrastructure (Epic 0); the session key holder (SessionSecrets, software-elements.md 0.3) is reused by US-01.05 on screen 1
Parts:              api (one operation), backend (Spring AI, session key holder), frontend (a small panel on the skeleton page), i18n, tests; db: no (the key is never stored)
Acceptance criteria:
                    AC-1: The skeleton page has an "AI check" panel: masked key field, a model shown from configuration (default the cheapest Claude model), a "Test" button; texts from the translation resource (en, de).
                    AC-2: "Test" calls one operation of `api/openapi.yaml` (contract first); the backend sends one short prompt to Claude with Spring AI and the key of this browser session, and returns the answer text and the model used.
                    AC-3: A wrong or missing key returns the error format of the contract with a reason the user understands (invalid key, no credit, rate limit, network); the page shows it in the panel's error state, the rest of the page stays (WFL-181).
                    AC-4: The key is held in engine memory for the browser session only (ADR-033): no table, column, log line, file, image or report contains it; after an engine restart it must be entered again.
                    AC-5: Automated tests run without a real key (stubbed model). One live check runs only when the developer's own key is present in the local `.env` (`ANTHROPIC_API_KEY`); without it the report states "live AI check: not run (no key)".
Edge cases:         Slow answer: loading state, bounded wait (timeout from configuration, CLAUDE.md 4); two tabs of one browser share the session key; a second browser needs its own key.
Data:               none (nothing persisted)
Non-functional:     pinned versions; no secret in any file, log or test report (CLAUDE.md 3, QR-SEC-01); cost: one short prompt per click
Screens:            the skeleton page of US-00.05 (no mockup screen); the real key entry is screen 1 (US-01.05)
BPMN:               level 1 "Check API key", "Key valid?", "Key rejected" (skill bpmn-model) — only the check, no project
Dependencies:       US-00.04 (backend, contract), US-00.05 (page)
Out of scope:       Projects, questions, harness choice (E-01, E-02); GitHub sign-in; storing a key
Estimate:           M
Source:             PO decision D-11 of 2026-11-14 (todo.md)
Status:             Draft
```
